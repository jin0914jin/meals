# 页面与交互流程

## 页面结构

第一版建议控制在 4 个页面：

- 首页：菜谱目录
- 详情页：查看单个菜谱
- 编辑页：新建或修改菜谱
- 分类页或弹层：管理/选择分类

如果想进一步压缩开发量，分类页可以先不单独做，用编辑页里的选择器完成。

## 首页：菜谱目录

首页信息结构：

- 顶部搜索框
- 分类筛选
- 菜谱列表
- 新建按钮

菜谱卡片建议展示：

- 图片
- 菜名
- 分类
- 更新时间

空状态：

> 还没有菜谱，先拍一道最近做过的菜。

## 详情页：查看菜谱

详情页展示：

- 大图
- 菜名
- 分类
- 食材
- 做法
- 备注
- 编辑入口
- 删除入口

删除需要二次确认，避免误删。

## 编辑页：新建/修改菜谱

编辑页字段顺序：

1. 图片
2. 菜名
3. 分类
4. 食材
5. 做法
6. 备注
7. 保存按钮

交互建议：

- 菜名必填
- 其他字段可以为空
- 没有保存直接返回时提示用户
- 保存成功后回到详情页或首页

## 分类

第一版内置分类：

- 荤菜
- 素菜
- 汤
- 主食
- 早餐
- 甜品
- 快手菜
- 其他

自定义分类可以放到第二版，第一版先保证流程轻。

## 用户路径

### 新增一道菜

打开小程序 -> 点击新建 -> 拍照/选图 -> 填菜名 -> 选择分类 -> 写做法 -> 保存

### 找一道菜

打开小程序 -> 搜索或点分类 -> 点击菜谱卡片 -> 查看详情

### 修改一道菜

进入详情页 -> 点击编辑 -> 修改图片或文字 -> 保存

### 删除一道菜

进入详情页 -> 点击删除 -> 二次确认 -> 返回首页

## 体验原则

- 先让用户快速记下来，不强迫填完整。
- 表单不要太长，备注字段可以承载临时想法。
- 图片是记忆入口，列表里要优先展示。
- 本地应用要让用户明确感觉“这是我的菜谱本”。
